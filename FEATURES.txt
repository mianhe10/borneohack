1.3 FEATURE 1 — RECORD SALES (Menu option 1)
----------------------------------------------------------------
State: log_sale

Entry: User types "1" from menu
  Bot: Explains 3 input methods:
       (a) Type sale as text
       (b) Send receipt/screenshot image
       (c) Send voice note

Sub-flow A: Text entry
  User types e.g. "Jual nasi lemak 3 bungkus RM15"
  Gemini extracts: amount, item, quantity, date
  Saved to users/{phone}.sales[] array
  Bot confirms entry + running total today
  State stays log_sale (continuous recording)
  User types MENU to exit

Sub-flow B: Image/receipt
  User sends photo of receipt or payment screenshot
  Gemini Vision extracts amount, items from image
  Same save + confirm flow as text

Sub-flow C: Document upload
  User sends PDF/document (e.g. invoice PDF)
  Same as image flow (Gemini Vision on document)

Sub-flow D: Voice note
  User sends audio message
  Gemini transcribes audio to text
  Text processed same as Sub-flow A

All entries append to users/{phone}.sales[] with:
  { amount, item, date, source: 'text'|'image'|'audio' }

1.4 FEATURE 2 — CREDIT SCORE (Menu option 2)
----------------------------------------------------------------
State flow: credit_q1 -> credit_q2 -> credit_q3 -> credit_confirm -> (score)

First time (no biz_age/bank/ssm on file):
  Q1: "Berapa lama perniagaan awak beroperasi?"
      (e.g. 3 bulan, 1 tahun, 5 tahun)
  Q2: "Ada akaun bank perniagaan?" (Yes/No)
  Q3: "Ada SSM / pendaftaran perniagaan?" (Yes/No)
  Saved: biz_age, has_bank_account, has_ssm
  Score calculated immediately

Returning user (answers on file):
  Bot shows current values:
    Bank account: yes (verified) / yes (unverified) / no
    SSM: yes (verified) / yes (unverified) / no
  User types YES to generate score / NO to update info

Score calculation (6 criteria, 100 pts total):
  1. Transaction Consistency  25 pts — daily sale frequency
  2. Revenue Strength         20 pts — recorded sales vs stated monthly rev
  3. Business Age             15 pts — months operating (biz_age + platform age)
  4. Formalization            20 pts — SSM (10) + bank account (10), bonus if verified
  5. Record Volume            10 pts — number of sales records
  6. Expense Discipline       10 pts — number of expense records

Levels:
  80-100  Cemerlang / Excellent
  60-79   Baik / Good
  40-59   Sederhana / Moderate
  0-39    Rendah / Low

Bot sends:
  - Score report (Gemini-generated explanation in BM/EN)
  - 3 improvement tips
  - Reminder to type SIJIL / CERTIFICATE

After score: checks Proactive Loan Trigger (see 1.9)

1.7 FEATURE 5 — LOAN AGENT (Menu option 5)
----------------------------------------------------------------
Express Q&A flow: 6 questions -> provisional score -> loan matches

State chain:
  express_loan_q1 -> q2 -> q3 -> q4 -> q5 -> q6
  -> loan_match_review -> loan_doc_upload -> menu

Q1: Business name
    e.g. "Kedai Makan Aisyah"

Q2: Industry
    1. Makanan & Minuman / Food & Beverage
    2. Fesyen & Pakaian / Fashion & Clothing
    3. Pertanian / Agriculture
    4. Perkhidmatan / Services
    5. Lain-lain / Others

Q3: Business age
    1. Baru (< 6 bulan) / New (< 6 months)
    2. 6-12 bulan / months
    3. 1-3 tahun / years
    4. 3+ tahun / years

Q4: Monthly revenue
    1. < RM2,000
    2. RM2,000 - RM5,000
    3. RM5,000 - RM10,000
    4. > RM10,000

Q5: Loan amount needed
    1. < RM10,000
    2. RM10,000 - RM50,000
    3. RM50,000 - RM100,000
    4. > RM100,000

Q6: Loan purpose
    1. Modal kerja / Working capital
    2. Beli peralatan / Equipment
    3. Kembangkan perniagaan / Business expansion
    4. Inventori / Inventory
    5. Lain-lain / Others

After Q6:
  Gemini generates provisional credit score (0-100) + reasoning
  matchLoans() queries Firestore loan_products
  4-factor match scoring:
    Interest rate fit      40%
    Loan amount fit        30%
    Credit score match     20%
    Document requirements  10%
  Top 3 matches sent with medals (gold/silver/bronze)
  Each match shows: bank name, amount, rate, match%, eligibility note

User types 1/2/3 to select loan
  state: loan_doc_upload
  Bot asks for supporting documents (IC, bank statement, SSM)

User sends image/document
  Creates Firestore loan_applications/BB-XXXXXXXX:
    { user_id, user_phone, user_name, bank_name, amount,
      loan_product_id, status:'pending', documents:[mediaId],
      express_data, created_at }
  Bot: "Application submitted! Ref: BB-XXXXXXXX"
  state: menu

1.13 SYSTEM FEATURES
----------------------------------------------------------------
Deduplication:
  In-memory Set of last 500 message IDs.
  Duplicate webhooks silently dropped.

Per-phone queue:
  Concurrent messages from same number processed sequentially.
  Prevents race conditions on Firestore writes.

Retry logic:
  Gemini calls: exponential backoff (3 attempts).
  Meta API calls: exponential backoff (3 attempts).

Language support:
  Bahasa Malaysia (bm) and English (en).
  Persisted per user in Firestore. Switch anytime with ENGLISH/BM.

Country support:
  MY (Malaysia)    — MYR, SSM, TEKUN/PUNB/BSN loans
  ID (Indonesia)   — IDR, NIB, KUR/PNM loans
  PH (Philippines) — PHP, DTI, SB Corp loans

SECTION 4: API ENDPOINTS
================================================================

GET /webhook
  WhatsApp webhook verification (Meta challenge)
  Params: hub.mode, hub.verify_token, hub.challenge

POST /webhook
  Receives all WhatsApp messages
  Returns 200 immediately, processes async via per-phone queue
  Routes by msg.type:
    text     -> handleText
    image    -> handleImage
    document -> handleImage
    audio    -> transcribeAudio

POST /notify_user
  Bank portal notifies MSME user of loan decision
  Body: { application_id, status, reviewer_notes }
  Returns: { ok, phone, status }
  Side effect: WhatsApp message sent to user

Static files served from /public/
  GET /              -> index.html (landing)
  GET /dashboard     -> dashboard.html (MSME)
  GET /bank          -> bank.html (bank portal)
  GET /app.js        -> main PWA JS
  GET /style.css     -> styles
  GET /manifest.json -> PWA manifest
  GET /sw.js         -> service worker
