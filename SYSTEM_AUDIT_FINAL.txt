PART 4: CREDIT SCORING ALGORITHM (features/credit.js)
════════════════════════════════════════════════════════════════════════════════

6 factors, max 100 points total:

1. Transaction Consistency (max 25)
   - Counts unique dates in sales[]
   - ≥20 dates = 25pts | ≥10 = 20pts | ≥5 = 14pts
   - 2-4 dates: ratio of unique_days / day_span * 8 + 2 (2-10pts)
   - 1 date = 3pts | 0 = 0pts

2. Revenue Strength (max 20)
   - Compares avg_monthly_sales vs stated monthly_revenue
   - ratio ≥1.0 = 20pts | ≥0.75 = 16pts | ≥0.5 = 12pts | ≥0.25 = 8pts | else = 4pts
   - Has sales but no stated revenue = 6pts

3. Business Age (max 15)
   - declared biz_age (parsed to months) + months since registered_date
   - ≥60m = 15 | ≥36m = 12 | ≥12m = 9 | ≥6m = 6 | ≥3m = 4 | >0 = 2 | else = 1

4. Formalization (max 20)
   - SSM: ssm_verified=10pts | declared yes but unverified=7pts | unknown=2pts | no=0pts
   - Bank: bank_verified=10pts | declared yes but unverified=7pts | unknown=2pts | no=0pts

5. Record Volume (max 10)
   - ≥30 sales = 10 | ≥20 = 8 | ≥10 = 6 | ≥5 = 4 | ≥1 = 2 | 0 = 0

6. Expense Discipline (max 10)
   - ≥10 expenses = 10 | ≥5 = 7 | ≥2 = 4 | ≥1 = 2 | 0 = 0

Score levels:
  ≥80 = Cemerlang (Excellent)
  ≥60 = Baik (Good)
  ≥40 = Sederhana (Moderate)
  <40  = Rendah (Low)

PART 8: KNOWN GAPS AND ISSUES
════════════════════════════════════════════════════════════════════════════════

SECURITY
  [GAP] Webhook signature not verified
        Meta signs all webhook payloads with X-Hub-Signature-256 header.
        Current code ignores this. Any actor with the endpoint URL can forge
        webhook calls. Fix: validate signature against WHATSAPP_TOKEN.

  [GAP] /api/match-loans phone validation weak
        Cleans whitespace, checks /^\d{7,15}$/ — does not normalize international
        format (+60 vs 60 vs 060). Could cause duplicate rate-limit keys.

  [GAP] bank2026 access code is hardcoded in server
        Low risk for hackathon (shared secret pattern), but worth noting.

  [GAP] Rate limiter and dedup are in-memory only
        Resets on every server restart. On Render free tier, this resets
        frequently (spin-down after 15min idle). Not a security issue per se
        but rate limit is ineffective after cold starts.

DATA
  [GAP] score_breakdown is null for express-only users
        Users who completed express flow (6 questions) but never triggered
        "View Score" (option 2) will have no score_breakdown in their user doc.
        handleDocUpload saves score_breakdown: userData.score_breakdown || null.
        Bank review modal falls back to score_reasoning string. Acceptable.

  [GAP] documents[] stores Meta media IDs, not accessible URLs
        Meta media URLs expire after ~5 minutes. Stored IDs require a fresh
        Graph API call to retrieve. Bank portal displays IDs only, cannot
        view documents without additional /media/{id} API call implementation.

  [GAP] score_history entries have no dedup guard
        score_history uses FieldValue.arrayUnion (Firebase deduplicates by value).
        If same {date, score} recorded twice, Firebase deduplicates. Safe.
        But different scores on same date both get stored. Fine for sparkline.

  [GAP] Firestore composite index may not exist in new environments
        loan_applications query (user_id + submitted_at) requires composite index.
        Fallback exists (in-memory sort), but fallback fetches up to 20 docs
        unordered and trims to 5. Acceptable for demo scale.

FUNCTIONAL
  [GAP] No SPA routing — deep links not supported
        /dashboard.html works. But /dashboard.html?phone=xxx doesn't auto-login.
        User must type phone. Intentional for demo but limits UX.

  [GAP] Landing page token flow requires user to be already onboarded
        Apply {token} flow in WhatsApp looks up landing_signups doc and populates
        express_loan_data, then matches loans. But if user is brand new (no user
        doc exists), text.js creates a new user doc. The token flow then still
        runs matchLoans() on a minimal user profile, which may produce weaker
        matches than a fully onboarded user would get.

  [GAP] ASEAN map in bank portal uses approximate country centroids
        Dots are plotted by country, not precise state coordinates.
        State field in user doc is not mapped to lat/lng. Cosmetic only.

  [GAP] Revenue Trends chart on bank portal is simulated
        Bank portal chart shows "last 7 days" revenue, but this is constructed
        from aggregated user data, not real time-series. Cosmetic for demo.

  [GAP] chat.js has no conversation memory
        Each message is a fresh Gemini call with the full business data context
        but no prior conversation turns. User cannot reference previous answers.

  [GAP] No push notifications from dashboard
        Dashboard does not subscribe to Firestore real-time listeners.
        Status updates (e.g. loan approved) are visible only after manual refresh.

VERIFICATION
  [UNVERIFIED] Gemini Vision OCR accuracy on low-quality photos
        Works on clean PDFs/photos in testing. Degraded photos may fail fuzzy
        name matching. Fallback: marks unverified, prompts user to retake.

  [UNVERIFIED] Audio transcription quality for Malay accent
        Gemini handles standard BM but heavy dialect or slang may degrade.
        No fallback for failed transcription beyond "please try again" error.
